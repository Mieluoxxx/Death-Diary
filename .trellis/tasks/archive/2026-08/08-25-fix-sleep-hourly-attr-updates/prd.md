# 修复睡眠期间状态按小时变化

## Goal

睡眠加速期间，玩家的饱腹度、精力、生命值及其他按时间变化的生存状态应随着游戏时钟跨过每个整点逐次结算，并在每次结算后立即反映在顶部状态栏，而不是等睡眠事件结束后一次性呈现变化。

## Background

- `facilityAction.ts` 以 1、4、8 个游戏小时启动睡眠计时，并通过 `accelerateWorkTime` 将过程压缩到最多约 3 秒现实时间。
- `survivalLoop.ts` 的规则明确以每个游戏小时为结算单位：饱腹度按小时下降，睡眠期间精力和生命值按小时恢复。
- `playerAttrs.ts` 在每次属性变化后发送 `attr_change` 和 `session_updated`；`HomeScene` 收到事件后调用顶部状态栏的 `refresh()`。
- 旧实现曾在睡眠开始时直接按总时长增加精力和生命值；当前实现已改为依赖生存循环，不能重新引入总量一次性结算。
- 第一轮修复已保证小时规则逐次执行，但用户确认状态条动画仍等到加速睡眠结束后才完成。
- 原版 `AttrButton` 只在对应的 `<attr>_change` 事件中更新属性图标；每分钟时钟刷新只更新日期和时间，不会重置属性显示。
- 当前版 `HomeScene` 同时监听 `time_tick` 和 `session_updated`，每次都调用完整 `topFrame.refresh()`。加速睡眠时刷新近乎每帧发生，反复杀掉并重启尚未完成的 `420ms` 属性 tween。

## Requirements

- 睡眠期间每跨过一个世界时钟整点，必须恰好执行一次小时生存结算。
- 每次小时结算后立即持久化会话并发送 UI 刷新事件，使顶部状态栏能逐次显示变化。
- 属性条收到与当前动画目标相同的高频刷新时，必须保持既有 tween 继续运行；只有属性目标值实际变化时才允许重新定向动画。
- 时钟、日志或其他无关会话刷新不得延迟属性动画完成。
- 1、4、8 小时睡眠均遵循同一机制；不得在睡醒回调中按总时长额外补算属性。
- 非睡眠状态下的正常小时结算行为保持不变。
- 制作、设施操作和建筑升级等共享计时任务的进度与完成回调不得重复、遗漏或提前触发。
- 跨越昼夜、午夜或季节边界时，现有阶段、每日和天气回调仍按时间顺序执行。
- 修复前先建立能够重现问题的自动化测试；修复后同一测试必须通过。
- UI 动画回归必须覆盖中间状态和 tween 生命周期，不能只断言最终属性值。

## Acceptance Criteria

- [x] 从非整点开始 4 小时睡眠时，饱腹度在跨过的四个整点分别下降，而不是仅在睡醒时变化。
- [x] 同一过程中，睡眠恢复按每个整点逐次应用，且最终结果不存在少算或重复结算。
- [x] 每次属性变化均触发顶部状态栏可消费的刷新事件。
- [x] 同一个属性目标在高频 `time_tick` / `session_updated` 刷新下只启动一次 tween，不会被重复杀死并重启。
- [x] 4 小时睡眠期间，饱腹度和精力状态条在“你醒了”出现前完成至少一次可见变化。
- [x] 1 小时和 8 小时睡眠分别触发与所跨整点数量一致的小时结算。
- [x] 非重复计时任务只完成一次；重复小时回调在单次大时间步跨越多个区间时不会漏触发。
- [x] lint、类型检查、自动化测试和图集一致性检查全部通过。
- [x] 自动化测试能够在移除动画防重启逻辑后失败，防止只验证数据层的伪回归覆盖。
- [x] 在本地游戏中完成一次 4 小时睡眠视觉验证，确认状态条在睡眠结束前完成变化，而不只是出现变化箭头。

## Out of Scope

- 将按小时规则改为每帧或每分钟连续扣除/恢复。
- 调整饱腹度、精力、生命值的数值公式或床铺效率。
- 重做顶部状态栏动画和睡眠进度条视觉样式。
- 修改制作、升级等计时任务的游戏时长或加速倍率。

## Open Questions

- 无。现有代码已明确小时结算语义；实现阶段通过回归测试确定断点所在层级。
