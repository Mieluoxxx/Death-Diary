# 修复睡眠期间状态按小时变化 - 技术设计

## Boundary

睡眠只负责设置 `isInSleep` 并创建有期限的计时任务；饱腹消耗和睡眠恢复继续由 `survivalLoop.ts` 的小时规则拥有。修复不得把属性公式复制到 `facilityAction.ts` 或睡醒回调。

真实断点应通过测试在以下链路中定位：

`HomeScene.update` -> `timeClock.tickTimeClock` -> 小时计时回调 -> `runHourlySurvivalTick` -> `changeAttr` -> `session_updated` -> `topFrame.refresh`

## Proposed Design

### 1. 固定复现

增加确定性的时间推进测试，从非整点开始模拟 1、4、8 小时加速睡眠，记录：

- 每次小时回调的触发时间和次数；
- 饱腹度、精力和生命值在各整点后的值；
- `session_updated` / `attr_change` 事件序列；
- 睡眠任务完成回调的次数。

测试应先在当前实现上证明用户反馈对应的断点，避免先改共享计时器再反推原因。

### 2. 修复所有权层

根据复现结果选择最小修复：

- 若时间推进在单次时间步跨过多个区间时漏掉重复回调，则在 `timeClock.ts` 中按时间边界顺序推进，并让重复回调基于原计划边界递增，不能从最终 `nextTime` 重新起算。
- 若小时规则已逐次执行但 UI 未刷新，则修复事件订阅或刷新生命周期，不改计时器算法。
- 若睡眠结束回调过早清除 `isInSleep`，则调整同一时间点回调的优先级/顺序，使最后一个小时结算在清除睡眠状态前完成。

无论最终落点在哪一层，都保持 `survivalLoop.ts` 为属性公式唯一所有者。

### 3. 展示层根因与修复

原版的属性视图契约是事件定向的：`<attr>_change` 更新对应 `AttrButton`，分钟计时器只更新日期和时钟。当前版用一个宽泛的 `refresh()` 同时承担时钟和属性刷新，导致加速时间下相同属性目标被高频重复提交。

`AttrFillEntry` 应分别保存：

- `displayRatio`：当前屏幕已经绘制到的比例；
- `targetRatio`：当前 tween 正在追赶的目标比例；
- `tweenProxy`：活动 tween。

当新刷新给出的目标与 `targetRatio` 相同时，保持现有 tween，不调用 `killTweensOf`，也不重复播放变化箭头。只有目标真正变化时，才从当前 `displayRatio` 重新定向到新目标。tween 完成后统一落定显示比例和目标比例。

这保留现有 `420ms` 动画视觉，同时恢复原版“无关时钟刷新不会阻断属性显示更新”的契约。

### 4. 时间顺序与兼容性

若需要修改共享计时器：

- 对一个时间步内跨过的所有回调边界按时间升序处理；同一边界沿用现有优先级顺序。
- `process(delta)` 接收实际分段时间，累计进度总量与原时间步一致。
- 非重复任务的 `end` 只执行一次。
- 重复任务每跨过一个区间执行一次，不因大时间步跳过，也不产生漂移。
- 最终把会话时钟推进到目标时间，阶段和分钟事件保持可观察一致性。

## Testing Strategy

- 为时间调度行为增加 Bun 单元测试；必要时把纯调度计算提取为不依赖浏览器存储的小函数。
- 为睡眠规则增加最小集成测试，验证每小时属性值与事件次数。
- 为属性动画增加生命周期测试：第一次目标变化创建 tween；动画未完成时重复提交相同目标不得 kill/restart；新目标才允许重定向。
- 动画测试必须断言中间生命周期，而不只断言最终 crop 或属性值。
- 保留现有服务器测试，并运行全项目 lint/typecheck。
- 使用本地浏览器实际执行一次 4 小时睡眠，观察顶部属性条在进度完成前完成一次填充变化。

## Risks And Rollback

- 共享计时器影响制作、升级、昼夜和午夜回调，错误的 catch-up 逻辑可能导致重复奖励或重复夜袭。
- 通过非重复任务一次性完成、重复回调次数、昼夜/午夜边界顺序测试控制风险。
- 属性动画若仅用最终状态断言，会重现第一轮“测试通过但用户行为未修复”的假阳性；必须保留 tween 防重启测试。
- 修改保持集中；若共享调度器修复产生回归，可回退该提交而不迁移存档或数据结构。
